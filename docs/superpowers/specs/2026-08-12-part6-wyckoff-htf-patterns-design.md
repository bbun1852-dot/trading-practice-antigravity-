# chart-drill Part 6 — 차트패턴·와이코프·HTF (사후 스펙과 교정)

## 0. 이 문서가 사후 스펙인 이유

Part 5(추세선·채널 5종)는 `37e600f` 에서 리뷰까지 끝났다. 그 위에 커밋 하나(`d2fa9ba`)로
**30종이 한꺼번에 얹혔다** — 차트패턴 16 + 와이코프 11 + HTF 3, 태그 76 → 106종.
스펙도 태스크 분할도 calibrate 체크포인트도 없이 들어왔다.

되돌리지 않고 **교정해서 살린다.** 인과성이라는 가장 어려운 부분은 실제로 지켜져 있기
때문이다(§1). 대신 이 문서가 사후 스펙 역할을 하고, 아래 결함을 파트 관례대로 태스크로
쪼개 고친다.

## 1. 실측 — 무엇이 맞고 무엇이 틀렸나

10,000봉(BTC·ETH·SOL·XRP·LINK × 4h/1d × 1000봉, 창 끝 2026-08-01 고정)으로 측정했다.

### 맞은 것

- **인과성이 지켜진다.** 세 감지기 모두 `Pivot.barIndex`(= `pivotBar + n`, 확정 시점)로
  거른다. `assertNoLookAhead` 는 공허하지 않다 — 픽스처에서 HTF 32건/3종,
  와이코프 24건/1종, 차트패턴 21건/7종이 실제로 난다(감지기가 아무것도 안 내면
  `assertNoLookAhead` 자신이 던지므로 공허한 통과는 구조적으로 불가능하다).
- **`DEFAULT_CORE_K` 5 → 6 은 옳다.** 태그 우주가 76 → 106 으로 커지면서 K=5 는
  커버리지 중앙값 **59.3%** 로 게이트(60~80%)를 탈락한다. K=6 이 69.0% / 참고소멸 0.0%
  로 통과한다. 다만 위 주석이 옛 측정값(K=5 → 0.0%, K=6 → 4.8%)을 그대로 두었고
  `grader.test.ts` 는 여전히 5 를 단언해 **테스트가 깨져 있다**.

## 2. 순서가 설계다

**D2 를 먼저 고친다.** `htf_trend` 는 전체 유효 근거의 **5.8%(356회)로 3위 태그**다 —
오더블록 두 종 바로 다음이다. 이걸 억제하면 근거 대역이 비고, 그 자리에 와이코프 9종이
들어간다. 순서를 뒤집으면 대역이 먼저 터져서 D3 를 또 느슨하게 만들고 싶어진다.

이것이 이 파트의 **위험 체크포인트**다: 죽은 9종을 살리는 일과 유효 근거 게이트(8~15)는
정면으로 충돌한다. D2 로 확보한 대역이 9종을 감당하지 못하면 수명 재확정으로 간다
(파트마다 태그가 늘 때 `ZONE_MAX_BARS` 를 다시 재는 것은 이미 정착된 절차다:
50 → 35 → 30 → 25).

## 3. 기계 — 와이코프 국면 상태기계

현재 `wyckoff.ts` 는 봉마다 독립적으로 "거래량 터졌나 / 박스 뚫었나" 를 묻는 휴리스틱이라
**11종 중 2종밖에 낼 수 없다.** 나머지 9종은 전후 맥락이 있어야 정의되는 사건이기
때문이다 — AR 은 SC 다음에만, ST 는 AR 다음에만, LPS 는 SOS 다음에만 의미가 있다.

그래서 **박스권(TR) 에피소드를 단위로 하는 전방 상태기계**로 바꾼다. 전방 스캔이므로
봉 `i` 의 상태는 봉 `0..i` 만으로 정해지고, 인과성이 구조적으로 보장된다.

### 3.1 에피소드

```
none ──SC/BC──> climax ──AR──> range ──ST──> tested ──Spring/UT──> sprung
                                  │                                   │
                                  └──────────── SOS/SOW ──────────────┴──> markup
```

축적(강세)과 분배(약세)는 완전한 거울상이라 방향을 매개변수로 받는 엔진 하나로 쓴다.

- **TR 하단** = SC 저가 (분배면 TR 상단 = BC 고가)
- **TR 상단** = AR 고가 (AR 확정 시점에 고정된다 — 이후 봉이 무엇이든 안 움직인다)

에피소드는 SOS 이후 BU/LPS 까지 가면 완료되고, TR 높이의 2배 밖으로 벗어나거나
`TR_MAX_BARS` 를 넘기면 만료된다. 그 뒤 `none` 으로 돌아가 새 에피소드를 받는다.

### 3.2 사건 정의

| id | 국면 | 조건 (강세/축적 기준) | side |
|---|---|---|---|
| `wyckoff_ps` | A | 하락 중 + 거래량 ≥ 1.5× + 아래꼬리 ≥ 몸통 + 종가가 레인지 상단권 | bullish |
| `wyckoff_climax` | A | 거래량 ≥ `CLIMAX_VOL_MULT` × 평균 + 레인지 ≥ 2 ATR + 저점에서 반등 마감 | bullish |
| `wyckoff_ar` | A | SC 저가에서 ≥ `AR_MIN_ATR` 반등한 뒤 되돌림 시작 (고가 고정 → TR 상단) | bullish |
| `wyckoff_st` | B | TR 하단 근처 재방문인데 거래량이 SC 보다 낮음 | bullish |
| `wyckoff_spring_ut` | C | TR 하단 아래로 저가가 내려갔다 종가는 TR 안에서 마감 | bullish |
| `wyckoff_shakeout` | C | Spring 인데 침투 ≥ `SHAKEOUT_ATR` 이고 거래량 ≥ 2× — **spring 대신** 낸다 | bullish |
| `wyckoff_test` | C | Spring 이후 저가가 Spring 저가 위에서 멈추고 거래량이 더 낮음 | bullish |
| `wyckoff_sos_sow` | D | 종가가 TR 상단 위로 마감 + 거래량 ≥ 1.5× | bullish |
| `wyckoff_lps_lpsy` | D | SOS 이후 되돌림인데 저가가 TR 상단 위에서 유지 | bullish |
| `wyckoff_bu` | D | SOS 이후 TR 상단에 닿았다가 위에서 마감 | bullish |
| `wyckoff_utad` | C | **분배 전용.** ST 를 거친 뒤 상단 침투 후 회귀 — **spring_ut 대신** 낸다 | bearish |

**한 침투 사건은 정확히 한 태그만 낸다.** 강세 하단 침투는 격렬하면 `shakeout`,
아니면 `spring_ut`. 약세 상단 침투는 ST 이후면 `utad`, 아니면 `spring_ut`.
Part 4 의 `choch`/`msb_*` 가 98% 겹친 실수를 반복하지 않기 위한 규약이다.

**사건 하나는 에피소드당 한 번만 낸다.** 상태기계가 단조 전진하므로 자연히 보장된다.

### 3.3 PS 만 예외다

PS 는 SC **이전** 사건이라 에피소드가 없는 상태(`none`)에서 나야 한다. "SC 가 확정된
뒤에 돌아가서 PS 를 낸다" 는 불가능하다 — 그러면 PS 의 봉으로 잘랐을 때 안 나오므로
`assertNoLookAhead` 위반이다. 따라서 PS 는 자기 봉의 정보만으로 나야 하고, 본질적으로
가장 시끄럽다. 조건을 세게 걸고 쿨다운을 둔 뒤 §4 에서 실측으로 조인다.

## 4. 게이트

Part 5 와 같되 하나를 더한다.

1. **발화율**: 신규 태그 각각 1000봉당 150회 이하
2. **유효 근거**: 계열별 중앙값 **8~15** — `MEDIAN_MAX` 를 18 에서 **되돌린 값으로** 판정한다
3. **후보 밀도**: 계열별 1000봉당 15~40개
4. **핵심 근거 K**: 커버리지 중앙값 60~80%, 참고 소멸 5% 미만
5. **미래참조**: `assertNoLookAhead` 통과(공허하지 않게)
6. **결정론**: `drill` 2회 출력 완전 동일
7. **죽은 태그 0종**: 등재 태그 수 == 실측 배출 태그 수 ← **이번 파트의 게이트**

7번이 D1 의 재발 방지다. 등재만 하고 안 나오는 태그는 사용자를 벌주기만 하므로,
"구현했다" 의 정의를 **실데이터에서 실제로 배출된다** 로 못 박는다.

5. `MEDIAN_MAX` 복원과 calibrate 게이트 통과 — **위험 체크포인트**

## 7. 미결

- `htf.ts` 는 차트 타임프레임과 무관하게 `FACTOR = 4` 고정이고, 캘린더가 아니라 배열
  인덱스 0부터 4개씩 묶는다. 1d 차트에서 "4일봉" 은 실재하는 상위 타임프레임이 아니다.
  이번 파트는 발화 억제까지만 하고, 진짜 HTF 데이터 계층은 별도 파트로 남긴다
  (원래 `htf_*` 3종을 미뤄 둔 이유가 "데이터 계층 필요" 였다).
- 차트패턴 16종은 인과성·발화율 모두 통과하므로 이번 파트에서 손대지 않는다.
  `pattern_bull_pennant` 만 예외다.
