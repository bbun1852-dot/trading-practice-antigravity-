# 태그 선택 UX — 설계 결정

2026-08-13 · 결정자 Claude (사장 위임) · 상태 **확정**

이 문서는 결정과 근거만 담는다. 구현 스펙은 별도다.

---

## 결정

**태그 선택 화면은 taxonomy(tier/kind)가 아니라 사용자 본인의 34점 시트 행으로 묶는다.**

`src/quiz/ruleCheck.ts` 의 `PROFILES` 가 이미 그 구조를 갖고 있다. 문제의 타임프레임이
프로파일을 고르고(단타/스윙/장기), 그 프로파일의 행이 곧 선택 화면의 묶음이 된다.

---

## 왜 이게 문제였나

105종을 어떻게 고르게 할 것인가. 체크박스 105개는 쓸 수 없다.

그런데 이걸 위젯 문제로 보면 틀린다. 실제 상황은 이렇다 — 사용자는 차트를 보고 판단한 뒤
**왜 그렇게 봤는지**를 입력한다. 실측상 결정 시점 하나의 유효 근거 중앙값은 14개이고
핵심(K)은 6개다. 사용자가 낼 답은 3~8개쯤이다.

즉 **105개 중 5개쯤을 찾는 문제**다. 그리고 제약이 둘 더 있다.

- **헛다리는 감점이다.** UI 가 "일단 많이 찍고 보자" 를 유도하면 채점이 무의미해진다
- **이 도구는 차트 읽기를 연습시킨다.** 태그 이름 외우기가 아니다

## 판단 기준

1. **5개를 빨리 찾는가**
2. **남발을 억제하는가**
3. **태그 이름 지식이 아니라 차트 읽기를 시험하는가**

## 후보 비교

| 안 | 빠름 | 남발 억제 | 차트 읽기 | 판정 |
|---|---|---|---|---|
| 검색창(커맨드 팔레트) | ✓ | ✗ 훑기 쉽다 | ✗ 이름을 아는 사람이 유리 | 단독 탈락 |
| 카테고리(kind) 아코디언 | △ | △ | 중립 | pattern 31종이 그대로 남는다 |
| tier 우선 점진 공개 | ✓ | ✓ | 중립 | 나쁘지 않으나 tier 는 사람의 사고 단위가 아니다 |
| 차트 앵커(자리 클릭) | ✓✓ | ✓✓ | ✓✓ | **결함으로 탈락** — 아래 참조 |
| **34점 시트 행** | ✓ | ✓✓ | ✓✓ | **채택** |

### 차트 앵커를 탈락시킨 이유

개념적으로는 가장 좋았다. 자리를 지목하게 하면 남발이 억제되고 차트 읽기를 직접 시험한다.
그런데 **후보를 좁혀 주는 것 자체가 답을 흘린다.** 클릭한 자리에서 가능한 태그만 보여주면
시스템이 "여기 뭔가 있다" 를 알려주는 셈이다.

여기서 일반 원칙이 나온다:

> **선택 화면의 구성은 문제와 무관한 축으로만 정해야 한다.**
> 필터·정렬·강조 중 무엇이든 이 문제의 정답에 의존하면 그건 힌트다.

RSI 과매수나 MA 배열처럼 **차트의 특정 지점이 아니라 상태인 태그**가 있다는 문제도 있었다.

---

## 34점 시트가 답인 이유

### 1. 사용자 본인의 사고 단위다

이 시트는 사장이 직접 정리한 것이다. "유동성 청산", "FVG", "오더블럭" 은 이미 머릿속의
분류다. 반면 `T3/pattern 31종` 같은 taxonomy 묶음은 채점 내부 구조지 사람이 쓰는 언어가 아니다.

근거 고르기가 **"내 체크리스트를 걷는 일"** 이 된다. 훑어서 찍는 동선이 아니다.

### 2. 개념으로 묻는다

"유동성 청산이 있었나?" 는 태그 이름을 몰라도 개념을 알면 답할 수 있다. 기준 3번을 정확히 만족한다.

### 3. 이미 타임프레임을 안다

`ruleCheck(active, q.timeframe)` 가 프로파일을 고른다. 단타 문제에서 와이코프 11종을
앞에 내밀지 않는다. **taxonomy 로는 얻을 수 없는 이점이다.**

### 4. 문제와 무관한 축이다

행 구성·순서·태그 목록이 전부 프로파일 상수다. 이 문제에 뭐가 있는지 흘리지 않는다.
차트 앵커를 탈락시킨 그 결함이 여기엔 없다.

### 5. 105종을 빠짐없이 덮는다 (실측)

```
[scalp]    행 10개 — 행에 56종 / 미배점 49종 / 어디에도 없는 태그 0종
[swing]    행 14개 — 행에 85종 / 미배점 20종 / 어디에도 없는 태그 0종
[position] 행 12개 — 행에 75종 / 미배점 30종 / 어디에도 없는 태그 0종
```

**세 프로파일 모두 누락 0종.** 이게 결정을 굳힌 사실이다. 새로 분류 체계를 만들 필요가 없다.

행 크기도 감당된다 — 대부분 10종 미만, 가장 큰 행이 캔들 17종이다.

```
[문제 타임프레임] → 프로파일 자동 선택 (4h → 스윙, 1d → 장기)

┌─ 내 시트 (스윙 기준 14행) ────────────────────┐
│  추세 구조 (Structure)      9종  [핵심]        │
│  유동성 청산 (Sweep)        3종  [핵심]        │
│  FVG                        3종  [핵심]        │
│  거시 차트 패턴            15종  [핵심]        │
│  일반 오더블럭              3종  [핵심]        │
│  거래량                     5종                │
│  … (OBV·MA·추세선·피보·볼린저·RSI·MACD·캔들) │
└───────────────────────────────────────────────┘

┌─ 이 시간대 시트에 없는 근거 (20종) ─ 기본 접힘 ┐
│  와이코프 11종 / HTF 3종 / …                   │
└───────────────────────────────────────────────┘

[검색] — 보조 수단. 105종 전체 대상, 기본 동선은 아니다
```

### 미배점 태그를 반드시 보여줘야 하는 이유

단타 프로파일은 49종이 `unscored` 다. 34점에는 안 들어가지만 **100점 채점에는 여전히
유효 근거**다. 안 보여주면 사용자가 맞힐 방법이 없고, 그건 이 저장소가 가장 경계하는
실패다 — 등재됐는데 고를 수 없는 태그는 죽은 태그와 같다.

기본은 접어 두되 길은 막지 않는다. 본인 시트를 먼저 걷게 하려는 것이지 숨기려는 게 아니다.

### 캔들 17종을 쪼개지 않는 이유

가장 큰 행이지만 그대로 둔다. 캔들 패턴은 이름이 곧 그림이라(해머·장악형·도지) 목록으로
훑는 게 자연스럽다. 억지로 쪼개면 오히려 찾기 어려워진다.

---

## 하면 안 되는 것

구현할 때 유혹이 올 자리다. 못 박아 둔다.

**① 이 문제에 해당하는 행을 강조하거나 위로 올리지 마라.**
정답을 흘린다. 행 순서는 프로파일 상수 그대로여야 한다.

**② 감지된 태그를 미리 체크해 두지 마라.** 같은 이유다.

**③ "보통 이럴 때 함께 나오는 태그" 같은 추천을 넣지 마라.**
통계가 이 문제의 정답과 상관될 수밖에 없다.

**④ 오답노트 통계("자주 놓치는 태그")를 답안 작성 중에 보여주지 마라.**
채점 후 복기 화면에서만 쓴다. 작성 중에 보여주면 편향이 생긴다.

**⑤ 선택 개수에 상한을 두지 마라.**
헛다리 감점이 이미 억제 장치다. 상한을 두면 근거가 진짜 많은 문제에서 사용자가 손해를 본다.
대신 **현재 선택 수와 예상 감점을 실시간으로 보여준다** — 억제는 정보로 하는 것이지
금지로 하는 게 아니다.

---

## 이 결정이 건드리지 않는 것

- `taxonomy.ts` 의 tier/kind 는 그대로다. 채점 배점과 수명의 출처이고 그 역할은 유효하다.
  **선택 화면에 안 쓸 뿐이다.**
- `ruleCheck.ts` 의 34점 계산도 그대로다. 채점 주체가 아니라 별도 검증 패널이라는
  사장의 결정은 유지된다. 이 결정은 시트의 **분류 구조**만 빌려 쓴다.
